## Проблема
macOS не может читать Synology диски: MD RAID → LVM → btrfs с проприетарными Synology флагами.

## Структура диска Synology DS723+ (24TB)
```
/dev/disk4 (GPT):
  disk4s1 — 8.6GB Linux_RAID (swap)
  disk4s2 — 2.1GB Linux_RAID (система DSM)
  disk4s5 — 24TB  Linux_RAID (данные)

disk4s5 внутри:
  MD RAID superblock: offset 4KB, magic fc4e2ba9, data_offset=2048 sectors (1MB)
  LVM PV: pe_start=1152 sectors, VG=vg1, extent_size=8192 sectors (4MB)
  LV syno_vg_reserved_area: 3 extents (12MB), start extent 0
  LV volume_1: ~22TB, start extent 3
  btrfs: внутри volume_1
```

## Вычисление смещения btrfs
```python
md_data_offset = 2048 * 512       # 1MB
lvm_pe_start = 1152 * 512         # 589824
volume_1_offset = 3 * 8192 * 512  # 12MB (extent 3 * extent_size)
total_offset = md_data_offset + lvm_pe_start + volume_1_offset  # = 14221312 bytes
volume_1_size = 5719296 * 8192 * 512  # ~22TB
```

## Pipeline

### 1. Python NBD сервер на macOS
Файл `/tmp/nbd_server.py` — экспозит raw block device с offset через TCP (newstyle protocol).
```bash
sudo python3 /tmp/nbd_server.py /dev/disk4s5 14221312 23988466089984 10809 &
```

### 2. Lima VM (Ubuntu 24.04 ARM64)
```yaml
# /tmp/nas-disk.yaml
images:
  - location: "https://cloud-images.ubuntu.com/releases/24.04/release/ubuntu-24.04-server-cloudimg-arm64.img"
    arch: "aarch64"
cpus: 4
memory: "4GiB"
disk: "20GiB"
mounts:
  - location: "/Users/im_ast/Documents/nas"
    writable: true
```
```bash
limactl start --name=nas-reader /tmp/nas-disk.yaml --tty=false
```

### 3. Установка пакетов в VM
```bash
sudo apt-get install -y linux-headers-$(uname -r) build-essential btrfs-progs lvm2 nbd-client flex bison libelf-dev libssl-dev
```

### 4. Патч btrfs модуля (Synology flag 0x400000000 = 1<<34)
Стандартный btrfs отклоняет Synology проприетарный root flag.
```bash
# Извлечь btrfs source
sudo tar xf /usr/src/linux-source-*.tar.bz2 linux-source-*/fs/btrfs/

# Патч tree-checker.c
sudo sed -i 's/const u64 valid_root_flags = BTRFS_ROOT_SUBVOL_RDONLY |/const u64 valid_root_flags = BTRFS_ROOT_SUBVOL_RDONLY | (1ULL << 34) |/' /tmp/linux-source-*/fs/btrfs/tree-checker.c

# Компиляция ПРОТИВ УСТАНОВЛЕННЫХ HEADERS (не source!)
sudo make -C /lib/modules/$(uname -r)/build M=/tmp/linux-source-*/fs/btrfs modules -j4
```

**ВАЖНО:** Компилировать через `/lib/modules/.../build` а не из source tree — иначе vermagic не совпадёт и будет segfault.

### 5. Загрузка модуля и монтирование
```bash
sudo rmmod btrfs
sudo insmod /tmp/linux-source-*/fs/btrfs/btrfs.ko
sudo nbd-client 192.168.5.2 10809 /dev/nbd0
sudo mount -t btrfs -o ro /dev/nbd0 /mnt/nas
```

### 6. Копирование данных
Lima монтирует хост-директорию → можно rsync напрямую:
```bash
rsync -av --exclude='*.apk' --exclude='*.gguf' --exclude='apk_decoded/' \
  /mnt/nas/Documents/Projects/target/ /Users/im_ast/Documents/nas/target/
```

## Скорость
~500 KB/s через NBD → USB 3.0. Для 1.8GB ≈ 40 минут.

## Структура данных Synology
```
/mnt/nas/
  @appconf/        — конфигурация приложений
  @appdata/        — данные приложений
  @docker/         — Docker volumes
  @database/       — MariaDB и др.
  Documents/       — shared folder
  homes/           — домашние папки пользователей
  docker/          — Docker shared folder
```

## NBD сервер (полный код)
Сохранён в `/tmp/nbd_server.py`. Поддерживает newstyle negotiation, read-only, offset от начала устройства. Ключевые параметры: path, offset, size, port.
